1. Зміна даних (UPDATE)

Спочатку змінено тривалість рейсу з id = 3: значення duration_min замінено на 510 хвилин. Контрольна вибірка показала, що змінився лише цей рядок, а водій, маршрут і дата рейсу залишились без змін.

Далі збільшено на 10 км відстань маршруту з id = 5 (Одеса–Миколаїв). Контрольна вибірка показала, що значення distance_km змінилось зі 130.0 на 140.0. Умова WHERE id = ... гарантує, що змінюється лише потрібний рядок, а не вся таблиця.

2. Видалення рейсу (DELETE)

Перед видаленням кількість рядків у trips дорівнювала 10. Після видалення рейсу з id = 7 вона стала 9. Видалення фактового запису безпечне, бо на таблицю trips ніхто не посилається, тому жодних зв'язків воно не порушує.

3. Перевірка ON DELETE RESTRICT (водій)

Зроблено спробу видалити водія з id = 1, який має рейси в таблиці trips. SQLite відхилив видалення з повідомленням (вставте дослівно те, що показав ваш клієнт):

FOREIGN KEY constraint failed

Водія з бази не видалено, його рейси збереглись. Це підтверджує рішення, обране в Практиці 4: водія, який має рейси, видалити не можна. З бізнесової точки зору це правильно, бо історія рейсів пов'язана з відповідальністю за вантаж, обліком робочого часу й зарплатою, і втрачати її не можна.

4. Перевірка ON DELETE SET NULL (маршрут)

Щоб не пошкодити справжні дані, перевірку виконано на тестових записах. Додано тестовий маршрут «Тест–Видалення» і тестовий рейс, який на нього посилається. Перед видаленням у рейсі був заповнений route_id. Після видалення тестового маршруту рядок рейсу залишився в таблиці, а значення route_id стало порожнім (NULL). Видалення відбулося без помилки.

Це підтверджує рішення, обране в Практиці 4: маршрут можна прибрати з каталогу, при цьому записи про виконані рейси зберігаються. Після перевірки тестовий рейс видалено, щоб не залишати службових даних у базі.

5. Порівняння двох дій

Дві перевірки показали різну поведінку, як і було задумано:

при видаленні водія база заблокувала операцію (RESTRICT), бо цей запис не можна втрачати;
при видаленні маршруту база дозволила операцію, але обнулила зв'язок у пов'язаних рейсах (SET NULL), бо рейс лишається фактом виконаної роботи навіть без маршруту.
